# 产品与技术架构

## 信息架构

| 层级 | 页面 | 责任 |
| --- | --- | --- |
| 入口 | 首页 | 成人与安全定位、继续学习、3D 核心价值、阶段状态 |
| 必修 | 安全入门 | 同意、停止信号、状态检查、风险症状、安全剪和快速解除 |
| 路径 | 学习路径 | 以先修关系组织准备、基础技术和后续地面技法 |
| 发现 | 课程库 | 搜索；按阶段、部位、技法、绳长、时间、风险、伙伴和审核状态筛选 |
| 学习 | 课程详情 | 元数据、3D 播放器、逐步说明、风险、错误、检查与解除 |
| 练习 | 3D 练习室 | 最大化 3D、简化文字、保留全部安全状态与播放器控制 |
| 记录 | 我的进度 | 收藏、最近学习、已完成步骤、备注、复习标记、导入/导出 |
| 查询 | 术语库 | 统一定义、同义词与安全上下文 |

## 分层

```text
课程 JSON / TypeScript 数据
  ├─ 基本信息、前置、材料、版本、来源、审核状态
  ├─ 预校验姿势、绳索样条、镜头预设、风险区与解除方向
  └─ 绑缚/解除阶段、时间范围、当前绳段、检查点和常见错误

通用 3D 引擎                通用播放器
  ├─ 训练人物                  ├─ 播放 / 暂停 / 逐步 / 循环
  ├─ TubeGeometry 绳段         ├─ 时间轴 / 速度 / 任意步骤
  ├─ 视角、镜像、透明度         └─ 自动镜头与局部特写
  └─ 风险区、接触点、方向层

页面 UI                    本地学习记录
  ├─ 首页 / 路径 / 课程库       ├─ 收藏 / 完成 / 最近学习
  └─ 课程页 / 练习室 / 术语      └─ 视角 / 速度 / 备注 / 导入导出
```

课程内容不进入 React 页面组件。播放器只消费统一 `Course` 接口；新增课程应以数据与经审核的 3D 资产为主。

## 3D 实现

- Phase 1 使用原创程序化成年训练模型验证坐标与性能；Phase 2 已替换为 Microsoft Rocketbox 的 MIT 许可成年骨骼模型，并保留程序化模型作为加载占位与低性能降级。
- GLB 人物、2K/1K WebP 纹理与课程均按需加载；高性能设备使用 2K PBR 纹理，中等设备使用 1K 纹理，低性能设备不强制下载高精度人物。
- 人物双臂由固定骨骼姿势校准，使画面左侧腕部与既有预校验绳路坐标对齐；用户仍不能自由改姿势。
- 绳索拆成预校验 Catmull–Rom 样条；每段 `TubeGeometry` 只创建一次，播放时只更新索引 `drawRange`。
- 解除演练同样由课程数据驱动，按阶段反向缩短已有绳段；播放器不写死具体技法或解除顺序。
- 完成段、活动段、绳头、风险区、接触点和解除方向是独立图层。
- 暂停时 Canvas 使用按需渲染；播放时才连续渲染。DPR 根据设备等级限制为 1–1.5。
- 课程页面与 Three.js 通过 `React.lazy` 按需加载，首页不下载 3D 引擎。
- 低性能、禁用 WebGL 或“减少动态效果”设备可切换为 SVG 分步降级图。
- 后续人物 GLB 必须由项目自制、委托制作或采用允许公开再分发的明确许可资产，并保留来源、授权、转换、压缩、体型与姿势校验记录。

## 内容发布闸门

课程状态依次为 `draft → technical-review → expert-review → published`。UI 只把 `published` 标为“正式”；其他状态持续显示明显提示。每次课程修改必须增加版本与更新时间，并重新检查绳路穿模、风险部位、步骤文字和解除动画。
